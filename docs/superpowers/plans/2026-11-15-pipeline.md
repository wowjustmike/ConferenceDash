# ConferenceDash Data Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the scheduled, hands-off pipeline that discovers, extracts, deduplicates, verifies and publishes conference data into `data/events.json`, which the finished web app already reads.

**Architecture:** A Node/TypeScript CLI under `pipeline/`. Small single-purpose stages (fetch, extract, normalize, dedupe, verify, score, publish) pass plain `Candidate` objects. Sources are declared in `pipeline/sources/registry.yaml`. Every network and LLM call goes through an injectable client so all logic is unit-tested against saved fixtures. GitHub Actions runs it on a cron and commits `data/events.json` when it changes.

**Tech Stack:** Node 24, TypeScript, tsx, Vitest, zod (reused from the web app), `yaml`, `@anthropic-ai/sdk`, `cheerio` (HTML/JSON-LD), `node-ical` (iCal), `robots-parser`.

**Spec:** `docs/superpowers/specs/2026-11-15-conferencedash-design.md` (sections 3-7, 9 phases 2-4). Source rules: `docs/SOURCING.md`. Output contract: `web/src/lib/schema.ts` (`EventSchema`, `ConfEvent`, `TOPICS`).

## Global Constraints

- Output is `data/events.json`, an array of `ConfEvent` validated with `EventSchema` from `web/src/lib/schema.ts` (imported by relative path; do not fork the schema).
- Store facts only; never copy descriptions or images. Every event keeps `official_url` and every contributing source in `sources[]` with `fetched_at`.
- The organizer's official site is the source of truth; aggregators are leads only and never sufficient alone to publish.
- Respect robots.txt; generic user agent `ConferenceDashBot/1.0`; at most 1 request/second per host; honor ETag/Last-Modified.
- A run that returns zero results for a source never deletes or overwrites existing data. A lower-confidence record never overwrites a higher-confidence one.
- Model IDs come from env, defaulting to `claude-haiku-5-5` (extraction, tagging) and `claude-sonnet-5-5` (ambiguous dedupe, verification disputes). A per-run LLM-call cap (`MAX_LLM_CALLS`, default 300) is enforced.
- Fetched page text is untrusted data: LLM calls get no tools, output must pass schema validation, and any instruction inside page text is ignored.
- Freshness: events starting within 30 days re-verified daily; 30-180 days weekly; beyond 180 days monthly. Past events are archived (`status: "past"`), not deleted.
- Confidence below `PUBLISH_THRESHOLD` (0.6) is quarantined to `pipeline/out/quarantine.json`, not published.
- Secrets (`ANTHROPIC_API_KEY`, `TICKETMASTER_KEY`) come from the environment only; never written to files or logs.

## Review Focus

1. Empty or failed source fetch must keep the last good data and flag the source unhealthy, not wipe events.
2. "CES" / "CES 2027" / "International CES" from two sources must merge into one event; "SXSW 2027" vs "SXSW 2028" and two co-located events with different sites must stay separate.
3. Garbage LLM output (invalid JSON, past dates, missing fields, hallucinated cities, injected instructions in the page) is discarded, never published.
4. A site that blocks us in robots.txt, returns 403/429, or times out is skipped politely, with backoff, and reported.
5. Dates: a re-run must not flip a confirmed date range back to TBC, and a page showing only last year's edition must not be treated as confirming the new one.

### Task 7: LLM extractor

**Files:** `src/extract/llm.ts`, `test/extract/llm.test.ts`.

**Interfaces:** Consumes `config`. Produces
```ts
interface LlmClient { extract(args: { model: string; system: string; pageText: string; schema: object }): Promise<unknown> }
function createAnthropicClient(apiKey: string): LlmClient
class LlmBudget { constructor(max: number); take(): boolean; used: number }
```

### Task 8: Registry runner and source health

**Interfaces:** Registry entry: `{id: string; kind: 'ical'|'page'; url: string; venue?: string; city?: string; state?: string; type: SourceRef['type']; pages?: string[]}`. Produces

### Task 10: Deduplication and merge

**Files:** `src/dedupe.ts`, `test/dedupe.test.ts`.

**Interfaces:** Consumes `Candidate`, `LlmClient`. Produces
```ts
function matchKey(c: Candidate): string                       // slug(name sans year/"international"/"annual") + "|" + year + "|" + normalizedCity
function mergeCandidates(list: Candidate[]): MergedEvent[]     // groups by matchKey, then fuzzy name (token Jaccard >= 0.8, same year and city)
interface MergedEvent { candidate: Candidate; sources: SourceRef[]; agreeing: number; conflictingDates: boolean }
function resolveAmbiguous(client: LlmClient, budget: LlmBudget, pairs: [Candidate, Candidate][]): Promise<boolean[]>  // sonnet adjudication for 0.5 <= similarity < 0.8
```
Merge prefers the candidate with an `official_url`, then more complete fields; `conflictingDates` true when two sources disagree on dates.

### Task 11: Verification and scoring

**Files:** `src/verify.ts`, `src/score.ts`, `test/verify.test.ts`, `test/score.test.ts`.

**Interfaces:** Produces
```ts
interface Verification { reachable: boolean; datesConfirmed: boolean; cancelled: boolean; cityMatches: boolean; editionYearSeen: boolean }
function verifyOfficialSite(fetchText, llm: LlmClient, budget: LlmBudget, ev: {name: string; official_url: string; start_date: string; end_date: string; city: string}): Promise<Verification>
```

`verifyOfficialSite` first does a deterministic text check (month/day strings of the range plus the edition year and city); only unresolved cases call the LLM (adjudicate model). ### Task 12: Scheduling and publishing

**Files:** `src/schedule.ts`, `src/publish.ts`, `test/schedule.test.ts`, `test/publish.test.ts`.

**Interfaces:** Produces
```ts
type Tier = 'daily'|'weekly'|'monthly'
function dueForVerification(ev: ConfEvent, today: Date, tier: Tier): boolean   // <=30 days: every tier run; 31-180: weekly+; >180: monthly only
function mergeIntoExisting(existing: ConfEvent[], fresh: ConfEvent[], opts: {today: Date; healthy: boolean}): { events: ConfEvent[]; quarantined: ConfEvent[]; archived: number }
function writeEventsAtomic(path: string, events: ConfEvent[]): void            // validates with EventSchema, temp file + rename; throws without touching the file on invalid data
```
`mergeIntoExisting` keeps existing events absent from `fresh` (never deletes on missing), refuses to lower `confidence` or flip `dates_confirmed` true -> false, marks events whose `end_date` is before today as `status: 'past'`, quarantines fresh events below `config.publishThreshold`, and keeps `id` stable (`slug(name)-year`).
