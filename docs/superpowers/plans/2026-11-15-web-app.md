# ConferenceDash Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the static, filterable ConferenceDash web app (list, calendar, map, compare, drawer, mobile) that reads `data/events.json`, matching `Design/ConferenceDash.pdf`.

**Architecture:** A React + Vite single-page app. All filtering is client-side over one JSON file. Pure logic (schema, dates, filters, compare, URL state) lives in `web/src/lib` with unit tests; components are thin. The pipeline (Plan 2, separate) will later write the same `events.json`.

**Tech Stack:** React 18, TypeScript, Vite, Vitest + Testing Library, zod, Leaflet (`react-leaflet`), CSS variables (light/dark), no UI framework.

**Spec:** `docs/superpowers/specs/2026-11-15-conferencedash-design.md` (visual spec: `Design/ConferenceDash.pdf`, pages 1-8; desktop uses the **left sidebar** layout on p.1).

## Global Constraints

- Static build only; no runtime server. Data file is `data/events.json`; the app fetches `/events.json`.
- Filtering is client-side. Event fields: `id, name, start_date, end_date, dates_confirmed, city, state, venue, organizer, topics[], est_attendance (nullable), official_url, sources[], last_verified, confidence, status (active|cancelled|past)`.
- Topic taxonomy is fixed: Tech, Healthcare, Finance, Gaming, Marketing, Energy, Media, Hospitality, Automotive, Aviation, Retail, Entertainment, Cannabis, Education, Sports, Other.
- Store and show facts only; every event links to `official_url`. No descriptions or images.
- Badges: green "Verified" when `last_verified` is within 30 days; amber "Re-check due" when older than 60 days; amber "Dates TBC" when `dates_confirmed` is false.
- Only `status === "active"` events are shown.
- Desktop: left filter sidebar. Mobile (<768px): bottom-sheet filters. Light and dark themes.
- Sample seed data is placeholder; the UI must say "Sample data" until real data lands.

## Review Focus

1. A `YYYY-MM-DD` date must not shift a day in negative-UTC time zones (parse as local date, not `new Date(str)`).
2. An event spanning a month boundary or more than 7 days must render correctly in the calendar.
3. An event with `est_attendance: null` shows "—", sorts last, and is excluded only by an explicit size filter.
4. One malformed entry in `events.json` is skipped with a console warning; the app still loads.
5. A city with no known coordinates still appears in list/compare and is listed under "unmapped" on the map instead of crashing.
